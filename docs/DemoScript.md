## 금지 (다른 모든 규칙보다 우선)
- **발표 당일 즉흥 입력 금지.** 대본에 없는 문장을 입력하지 않는다. LLM 출력은 입력이 바뀌면 재현되지 않는다.
- **리허설에서 3회 연속 같은 판정이 나오지 않은 케이스는 대본에서 뺀다.** 들쭉날쭉한 입력을 "운 좋으면 되겠지"로 남기지 않는다.
- **미구현 기능을 구현된 것처럼 보여주지 않는다**(AC-034). 로드맵은 로드맵이라고 말한다.
- **국가·국민성 서술 금지**("한국 사람은 돌려 말한다", "일본에서는 🙏가 사과다" 등). 언어 구조 또는 당사자 합의로만 말한다(Planning Decision #6·#50·#71).
- 실패 시 **당황해서 재시도하지 않는다.** 각 장면의 폴백 경로로 즉시 넘어간다.

## 장면 2 — C6 하소연 → 티켓 변환 (0:50) 【데모 하이라이트, 절대 유지】

**입력 대본** (TestCases "C6 메인")

```
이거 왜 자꾸 늦어지는 거예요? 저번 스프린트 때도 이러셨는데, 계속 이러면 저희도 일정을 못 맞춥니다. 답답하네요.
```

**보여줄 것**
1. 감정이 **삭제되지 않고** [우려 수준]=높음 메타 정보로 보존된다(AC-018)
2. 동시에 [문제 정의] / [영향·리스크] / [요청 사항]이 있는 실행 가능한 티켓이 생성된다(AC-017)
3. 근거가 없는 항목은 **"미정"** 으로 남고 지어내지 않는다(AC-020)
4. **바로 이어서 오탐 방지 대조군을 넣는다**(AC-058) — `이 부분 확인이 좀 필요할 것 같은데 언제쯤 가능하실까요?` → **티켓 변환 옵션이 뜨지 않는다.** 한 문장으로 말한다: *"감정 신호가 없으면 티켓으로 바꾸자고 하지 않습니다."*

**말할 것**: 이게 KEY 3이다. 경쟁 도구는 사내 동료에게 예의 있게 말하는 걸 돕고, 우리는 **서로 다른 회사가 감정싸움 없이 목표를 향하게** 한다. 검색한 경쟁 서비스(Tonero·checktone·Slack AI·Superhuman)에서 이 기능을 **찾지 못했다** — 단, **"없다"고 단정하지 않는다**(미발견은 부재 증명이 아니다).

**결정 권한 상태(AC-050)를 화면에 띄우게 되면**: 반드시 **"가설 단계"**라고 말한다(추정, T38 인터뷰 검증 대기 — Planning Decision #54).

## 장면 3 — C2 긴급도 보존 + 한국어 어미 (0:50) 【절대 유지, 차별화 최대】

**입력 대본 ①** (TestCases U-01)

```
혹시 오늘 중으로 가능하실까요?
```

**보여줄 것 — 3단 비교**

| 구분 | 출력 |
|---|---|
| 원문 | 혹시 오늘 중으로 가능하실까요? |
| 일반 번역 | Would it maybe be possible today? |
| 우리 변환 | I need this by EOD today. Please confirm if that's not feasible. |

가운데 "일반 번역"은 **미리 캡처한 정적 이미지**를 쓴다. 발표 중에 외부 번역기를 라이브로 열지 않는다(네트워크·시간 리스크).

**입력 대본 ②** (TestCases P-02 — 보존 필터 실증)

```
결제 API 죽었습니다. 지금 주문 전부 실패 중이에요. 당장 확인 부탁드립니다.
```

**보여줄 것**: 변환문에 **결제 API 장애 / 주문 전량 실패 / 즉시 확인 요청**이 그대로 남아 있다(AC-006). 대조군 "`When you get a chance, could you take a look at the payment API?`"를 **정적 이미지**로 나란히 놓는다.

**말할 것**: 이건 문화 일반화가 아니라 **언어 구조**다. 한국어는 긴급도를 어미와 부사에 싣고, 영어는 어휘에 싣는다. 직역하면 긴급도가 0이 된다. 수치를 말할 때는 **AC-045·AC-006의 실제 통과 수치만** 말하고, 측정 전에는 수치를 말하지 않는다.

**대비 입력** (U-07)
```
바쁘신 와중에 죄송하지만, 결제 API 장애 건 확인 부탁드립니다.
```

## 장면 4 — C4 역번역 + 오해 경고 + 오역 감지 (0:40)

**입력 대본** (TestCases M-01)

```
확인 부탁드립니다.
```

**보여줄 것**
1. 오해 사전 경고: *"상대가 '단순 참고'로 받아들여 액션을 취하지 않을 수 있음"* — 인용 구간·예상 오해·근거 3요소
2. 역번역(백트랜슬레이션)으로 발신자가 직접 검증 + **"완전한 검증이 아니라 1차 안전장치" 한계 문구**(AC-002)
3. **바로 이어서 중립 케이스를 입력해 경고가 뜨지 않는 것을 보여준다** (M-07: `8월 12일 14시에 릴리스합니다.`)

**말할 것**: 경고가 항상 뜨는 게 아니라 **근거가 없으면 아무것도 만들지 않는다.** 이게 AC-043의 절반(중립 4건 빈 배열)이고, "AI가 아무 말이나 지어내는 거 아니냐"는 질문의 답이다.

> 3번을 반드시 넣는다. 경고가 뜨는 장면만 보여주면 "위험을 과장하는 도구"로 보인다.

**여유가 있으면 오역 감지 1건 추가** (TestCases 기능별 데모 케이스)
```
이 건은 일단 홀딩하고 가시죠.
```
역번역이 **"이 안건은 보류하고 진행하겠습니다"**로 돌아오면 정상, **"이 건을 붙잡고 가겠다"** 류로 돌아오면 **오역을 잡아낸 성공 사례**로 말한다.

## 장면 5 — C3: 학습 전/후 · 같은 말 세 사람 (0:50)

### (a) 학습 전 / 학습 후 — 발신자 1인 2상태 【컷 안전, 가장 늦게 제거】

**보여줄 것**: 같은 발신자(박지훈)의 프로필을 **diff 0건 상태**와 **10건 반영 상태**로 각각 놓고, 같은 원문에 대한 **AI 제안문이 달라지는 것**을 보인다. 반영된 패턴은 **"완충 삽입"(전역 3회)**과 **"기한 명시"(전역 3회)**이고, **"이모지 제거"는 1회뿐이라 반영되지 않았다**(AC-013).

**말할 것**: "3번 이상 같은 방식으로 고쳤을 때만 반영합니다. 한 번 고친 건 학습하지 않습니다 — **노이즈를 프로필에 넣지 않기 위해서**입니다."

> ⚠️ **서술 금지(중요)**: **"타나카에게 3번 고쳐서 반영됐다"고 말하지 않는다.** 3회 카운팅은 **사용자 전역**이다(PRD Planning Decision #35·#75). 올바른 문장: **"이 패턴이 전체 발송에서 3번 나타나 반영됐습니다."**
> 이 (a)는 **#24에 의존하지 않으므로 컷돼도 살아남는다** — KEY 2의 컷 안전 근거다(Planning Decision #76).

### (b) COMPARE-01 — 같은 말, 세 사람 【조건부】

> ⚠️ **선행 조건**: **#24 쌍방 규약(T41·T42, P2)이 살아 있을 때만** 시연 가능하다. **컷된 경우 → (b)만 통째로 빼고 (a)로 장면을 끝낸 뒤 장면 6으로 넘어간다.** 대체 설명을 즉석에서 만들지 않는다. 발표 자료에서도 KEY 2를 로드맵으로 강등한다(Planning Decision #79).

**입력 대본** (TestCases.md COMPARE-01)

```
결제 모듈 스펙을 아직 못 받았습니다. 이번 주 안에 주셔야 다음 주 개발 착수가 가능합니다.
```

**보여줄 것**: 같은 원문을 **타나카(완곡·격식) / Michael(직설·결론 우선) / Sarah(기본 변환 + "아직 학습된 내용이 없습니다")** 3인에게 보낸 결과를 나란히 놓는다.

**말할 것 (확정 멘트)**:
> "같은 말인데 세 가지로 나갑니다. 그리고 세 번째는 아직 학습이 안 됐다는 걸 숨기지 않습니다."

**이어서 반드시 덧붙일 한 문장 (KEY 2)**:
> "우리는 상대의 성향을 **추측하지 않습니다.** 상대가 **직접 합의한 규칙**을 받아서 씁니다."

**"그냥 번역 언어가 달라서 아닌가요?" 질문이 나오면 — Michael ↔ Sarah를 가리킨다**
명세상 수신자별로 출력이 갈리는 근거는 **① 언어쌍 ② 수신자 타임존 ③ #24 규약** 셋뿐이다. **타나카와 Michael은 언어쌍만으로도 갈리지만, Michael과 Sarah는 둘 다 영어권이라 규약이 없으면 갈리지 않는다.** 그래서 Sarah 대조군이 이 장면의 증거다(PRD Planning Decision #76).

**하지 말아야 할 말**: "C3가 수신자별로 학습합니다" / "수신자의 수용 방식을 학습합니다" — **명세와 불일치하므로 폐기된 문구다**(Planning Decision #58).

## 장면 6 — C1 긴급도 분류 + override (0:20)

장면 3 ②의 입력을 재사용한다(새 입력을 만들지 않는다).

**보여줄 것**: CRITICAL 판정 + **판단 근거 문장**(AC-003) → 사용자가 등급을 **바꿀 수 있다**(AC-004) → CRITICAL은 예약·지연 경로를 타지 않고 톤 정제만 적용된다(AC-005).

**override 시연(권장)**: TestCases **T-U05**("버튼 색상이 조금 어두운 것 같습니다")를 넣고, **오분류가 나오면 그 자리에서 override 버튼을 누른다.** 실수를 숨기지 않는 편이 신뢰에 낫다 — "AI가 틀릴 수 있고, 그래서 사람이 마지막에 확정합니다"로 이어간다.

**말할 것**: AI가 정하지 않는다. **AI는 근거를 제시하고 사람이 확정한다.** 자동 발송 경로는 코드에 아예 없다(AC-010).

**시차 대조(여유 있을 때만)**: 한국 화요일 15:00 → **Michael(LA)은 현지 화요일 23:00** → 예약 발송 제안 / **타나카(일본)는 시차 0** → 경고 없음 → *"시차가 없어도 문화 장벽은 남습니다."* ⚠️ **예약 발송은 R3(T32, P2)** 이므로 **컷되면 타임존 표시까지만 보여주고 예약 발송을 말하지 않는다**(AC-034).

## 장면 7 — 층 1 범용 오버레이 (0:30)

**동작 대본**: 데모용으로 열어둔 페이지에서 텍스트를 **드래그 선택** → 플로팅 버튼 클릭 → 중재 패널 → 클립보드 복사.

**보여줄 것**: 지정된 사이트가 아니어도 동작한다는 것. **T55 스파이크에서 실제로 확인된 사이트에서만 시연**하고, 확인하지 않은 사이트 이름을 "동작합니다"라고 말하지 않는다.

**말할 것**: 일본 1위는 Teams이고 Slack은 두 조사 모두 7%대다(수치를 말할 때는 **두 조사를 병기**한다 — Planning Decision #67). 중국은 DingTalk·WeCom·Feishu가 합계 92%다. **단일 플랫폼에 붙는 도구는 이 경계를 못 넘는다.** 우리는 브라우저 안이면 어디서든 동작한다 — 다만 **중국 툴은 네트워크가 분리돼 있어 확장으로도 커버할 수 없다**는 한계를 그대로 말한다.

> 한계를 먼저 말하는 게 강하다. 숨기면 질문으로 돌아온다.

**Teams를 언급할 때**: "층 1로 이미 동작하며 **삽입 자동화는 로드맵**"이라고 말한다. **"Teams를 지원합니다"라고 말하지 않는다**(층 2 미구현 — Planning Decision #68, AC-034).

**폴백**: 확장 로드가 실패하면 **즉시 웹앱으로 전환**한다. 웹앱은 이 상황을 위해 준비된 백업 경로다(Planning Decision #3).
