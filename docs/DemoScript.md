## 금지 (다른 모든 규칙보다 우선)
- **발표 당일 즉흥 입력 금지.** 대본에 없는 문장을 입력하지 않는다. LLM 출력은 입력이 바뀌면 재현되지 않는다.
- **리허설에서 3회 연속 같은 판정이 나오지 않은 케이스는 대본에서 뺀다.** 들쭉날쭉한 입력을 "운 좋으면 되겠지"로 남기지 않는다.
- **미구현 기능을 구현된 것처럼 보여주지 않는다**(AC-034). 로드맵은 로드맵이라고 말한다.
- **국가·국민성 서술 금지**("한국 사람은 돌려 말한다", "일본에서는 🙏가 사과다" 등). 언어 구조 또는 당사자 합의로만 말한다(Planning Decision #6·#50·#71).
- 실패 시 **당황해서 재시도하지 않는다.** 각 장면의 폴백 경로로 즉시 넘어간다.

## 장면 2 — C6 하소연 → 티켓 변환 (0:50) 【데모 하이라이트, 절대 유지】

**입력 대본** (TestCases "C6 메인")

```
이거 왜 자꾸 늦어지는 거예요? 저번 스프린트 때도 이러셨는데, 계속 이러면 저희도 일정을 못 맞춥니다. 답답하네요.
```

**보여줄 것**
1. 감정이 **삭제되지 않고** [우려 수준]=높음 메타 정보로 보존된다(AC-018)
2. 동시에 [문제 정의] / [영향·리스크] / [요청 사항]이 있는 실행 가능한 티켓이 생성된다(AC-017)
3. 근거가 없는 항목은 **"미정"** 으로 남고 지어내지 않는다(AC-020)
4. **바로 이어서 오탐 방지 대조군을 넣는다**(AC-058) — `이 부분 확인이 좀 필요할 것 같은데 언제쯤 가능하실까요?` → **티켓 변환 옵션이 뜨지 않는다.** 한 문장으로 말한다: *"감정 신호가 없으면 티켓으로 바꾸자고 하지 않습니다."*

**말할 것**: 이게 KEY 3이다. 경쟁 도구는 사내 동료에게 예의 있게 말하는 걸 돕고, 우리는 **서로 다른 회사가 감정싸움 없이 목표를 향하게** 한다. 검색한 경쟁 서비스(Tonero·checktone·Slack AI·Superhuman)에서 이 기능을 **찾지 못했다** — 단, **"없다"고 단정하지 않는다**(미발견은 부재 증명이 아니다).

**결정 권한 상태(AC-050)를 화면에 띄우게 되면**: 반드시 **"가설 단계"**라고 말한다(추정, T38 인터뷰 검증 대기 — Planning Decision #54).

## 장면 3 — C2 긴급도 보존 + 한국어 어미 (0:50) 【절대 유지, 차별화 최대】

**입력 대본 ①** (TestCases U-01)

```
혹시 오늘 중으로 가능하실까요?
```

**보여줄 것 — 3단 비교**

| 구분 | 출력 |
|---|---|
| 원문 | 혹시 오늘 중으로 가능하실까요? |
| 일반 번역 | Would it maybe be possible today? |
| 우리 변환 | I need this by EOD today. Please confirm if that's not feasible. |

가운데 "일반 번역"은 **미리 캡처한 정적 이미지**를 쓴다. 발표 중에 외부 번역기를 라이브로 열지 않는다(네트워크·시간 리스크).

**입력 대본 ②** (TestCases P-02 — 보존 필터 실증)

```
결제 API 죽었습니다. 지금 주문 전부 실패 중이에요. 당장 확인 부탁드립니다.
```

**보여줄 것**: 변환문에 **결제 API 장애 / 주문 전량 실패 / 즉시 확인 요청**이 그대로 남아 있다(AC-006). 대조군 "`When you get a chance, could you take a look at the payment API?`"를 **정적 이미지**로 나란히 놓는다.

**말할 것**: 이건 문화 일반화가 아니라 **언어 구조**다. 한국어는 긴급도를 어미와 부사에 싣고, 영어는 어휘에 싣는다. 직역하면 긴급도가 0이 된다. 수치를 말할 때는 **AC-045·AC-006의 실제 통과 수치만** 말하고, 측정 전에는 수치를 말하지 않는다.

**대비 입력** (U-07)
```
바쁘신 와중에 죄송하지만, 결제 API 장애 건 확인 부탁드립니다.
```

## 장면 4 — C4 역번역 + 오해 경고 + 오역 감지 (0:40)

**입력 대본** (TestCases M-02 — v4.1, Planning Decision #123로 M-01에서 교체)

> 🔴 **(v4.1, Planning Decision #123) M-01("확인 부탁드립니다.")에서 교체됨** — T35 부분 리허설(2026-08-09)에서 M-01이 로컬 라이브 LLM 호출에 오해 경고를 재현하지 못함을 발견(원인 미진단). M-02는 라이브 1회 실행에서 즉시 경고를 재현했고 TestCases.md:65의 기대 오해와 의미상 일치한다. **단 M-02도 3회 독립 재현 검증은 아직 완료되지 않았다**(`llm_cache`로 인해 동일 입력 재실행이 캐시를 반환 — T35 잔여 작업). ~~M-01 원문은 이력 보존을 위해 위 결정 각주에 남긴다~~

**보여줄 것**
1. 오해 사전 경고: *"가능하시면"이라는 표현이 선택 사항으로 읽혀 우선순위에서 밀릴 수 있음* — 인용 구간·예상 오해·근거 3요소
2. 역번역(백트랜슬레이션)으로 발신자가 직접 검증 + **"완전한 검증이 아니라 1차 안전장치" 한계 문구**(AC-002)
3. **바로 이어서 중립 케이스를 입력해 경고가 뜨지 않는 것을 보여준다** (M-07: `8월 12일 14시에 릴리스합니다.`)

**말할 것**: 경고가 항상 뜨는 게 아니라 **근거가 없으면 아무것도 만들지 않는다.** 이게 AC-043의 절반(중립 4건 빈 배열)이고, "AI가 아무 말이나 지어내는 거 아니냐"는 질문의 답이다.

> 3번을 반드시 넣는다. 경고가 뜨는 장면만 보여주면 "위험을 과장하는 도구"로 보인다.

**여유가 있으면 오역 감지 1건 추가** (TestCases 기능별 데모 케이스)
```
이 건은 일단 홀딩하고 가시죠.
```
역번역이 **"이 안건은 보류하고 진행하겠습니다"**로 돌아오면 정상, **"이 건을 붙잡고 가겠다"** 류로 돌아오면 **오역을 잡아낸 성공 사례**로 말한다.

## 장면 5 — C3: 학습 전/후 · 같은 말 세 사람 (0:50)

### (a) 학습 전 / 학습 후 — 발신자 1인 2상태 【컷 안전, 가장 늦게 제거】

> 🔴 **(v2.3 전제 — 어기면 이 장면이 무너진다, PRD Planning Decision #85 / AC-059)**: 여기서 말하는 **"학습 전"은 온보딩 자기신고는 채워져 있고 diff만 0건인 상태**다. **온보딩을 건너뛴 빈 계정이 아니다.** v2.7부터 온보딩 스킵이 허용되므로, 시드 계정이 스킵 상태면 "학습 전" 화면에 **아무것도 없어** 학습 전/후 대비가 사라진다. 시연 전에 **T61이 프로필을 실제로 채워 두었는지 확인**한다(데이터 준비 체크리스트 #1-b).

> ⚠️ **서술 금지(중요)**: **"타나카에게 3번 고쳐서 반영됐다"고 말하지 않는다.** 3회 카운팅은 **사용자 전역**이다(PRD Planning Decision #35·#75). 올바른 문장: **"이 패턴이 전체 발송에서 3번 나타나 반영됐습니다."**
